# AGENTS.md

Guide for coding agents working on **Universe Library**, a small Django 5.2 (LTS) educational site about space. Read "Concept" and "State of the project" first; the galaxy section further down is long because the galaxy took most of the effort, not because it matters more than the rest.

> **Visual decisions live in [DESIGN.md](DESIGN.md)**: colour (four brand hues and their ramps), the LiftKit golden-ratio scale, type, shape, depth, motion, imagery and the logo. Tokens are in `static/Styles/Tokens.css` (`--ul-*`); use them instead of literals. Read DESIGN.md before any change someone will see.

> This file and DESIGN.md are tracked in git (AGENTS.md since 0.8.2.9). The `.claude/` folder (agent tooling, including `launch.json`) is gitignored and stays local.

---

## 1. Concept

- **What it is:** an educational library of the universe for beginner-to-intermediate readers. It has two kinds of page:
  1. **The galaxy (`/`)**: an interactive, scientifically honest 3D Milky Way. It is the front door and the map.
  2. **System pages (`/Solar`, `/Trappist`, …)**: one per star system. A top-down animated orrery sits on the right, and on the left are information "frames" holding text, images, video, audio and tables.
- **Pillars**, in priority order:
  1. **Educational and honest.** Real positions, real distances, sources credited, and scale cheats always labelled ("shown closer", "log-scaled").
  2. **Visual aesthetics.** The site should feel like a planetarium rather than a textbook. The house look is deep black, violet/blue star tints, glowing accent borders and the display fonts in `static/Fonts`.
  3. **Modularity.** Adding a system should need data only: DB rows plus a `galaxy_placement` row.
  4. **Embedded media.** Content is a mix of text, images, video and audio.
- **Deliberately removed. Don't bring any of these back:** the calculator, index, about, articles, the nav bar, and the Swiper card deck that used to be the main page (`CardType`/`DeckType`, `UniverseScripts.js`, the Swiper vendor files).
- **No external requests from the galaxy page.** Three.js is vendored, so the page works on a LAN with no internet. System pages still hotlink their images (see §2).

## 3. Run it locally (Windows)

```powershell
py -3.11 -m venv .venv                      # Django 5.2 supports Python 3.10-3.13; avoid 3.14
.venv\Scripts\python -m pip install -r requirements.txt   # file is UTF-16; pip handles it
# .env in repo root (gitignored) must contain: SECRET_KEY=<random string>
.venv\Scripts\python manage.py runserver 0.0.0.0:8000     # 0.0.0.0 = reachable from other LAN devices
```

- The existing `.venv` runs Python 3.11.9 with Django 5.2.19 (LTS, supported to April 2028; upgraded from 4.2.6 on 2026-11-26, after 4.2 reached end of life), django-compressor 4.7, django-libsass 0.9, django-sass-processor 1.4.2 and python-decouple 3.8. Django 6 needs Python 3.12 or later, so it waits for a new venv.
- `settings.py` reads `SECRET_KEY` (required), `DEBUG` (default `True`), `ALLOWED_HOSTS` (comma-separated, default `*`) and `PUBLIC_SITE` (default `False`; set it to `True` before publishing beyond the owner's own use: `views.with_images` then leaves out the 14 images whose licence starts "Fair use") through `python-decouple`.
- `.claude/launch.json` (local only: `.claude/` is gitignored, so create it if missing) defines a `django` preview config. Its args hard-code port 8000. If the pane reports that it "assigned 8001", the server still listens on **8000**, so browse to that port.
- `db.sqlite3` is **committed** and holds the content. Never delete it or run `flush`. **It is the source of the content and is edited as we go** (owner, 2026-11-26: SQLite is enough for this), so a change to it is committed and pushed like code; `origin/master` holds the current copy. The `starsystems` models are `managed = False`, so migrations never touch those tables; edit content with a SQLite tool or a short script.

## 5. Routing

- `/` → the galaxy, and nothing else.
- `/Solar`, `/AlphaCentauri` → the predefined Python systems.
- `/<systems.name_NAME>` → DB systems (Trappist, Trebia, Polaris, Sirius, Mira). `starsystems/urls.py` **queries the DB at import time** to register these, so a new row needs a server restart. A name containing a space would register a URL with a space while the galaxy links to the space-stripped href, so keep DB names space-free.
- Every page is one level deep, and links are relative (`../static/...`, `href="Trappist"`). Keep it that way or the links break. System pages link back to `/`.
- The galaxy's system markers and dock rows are plain `<a href>`, so nothing was orphaned by removing the deck.

## 6. System pages

### Content model (DB)
- **`systems`**: name, three colours, thumbnail (`LinkImages/` file), icon (`Icons/` file; missing → `AlternativeIcon.ico`), short description.
- **`objects`**: belongs to a system and optionally to a parent object (moons). Holds size (vh), colours, glow, orbit size (vmin) and orbit period (s).
- **`panels`**: belongs to either a system (the overview frames) or an object. `type_ID` → `panel_types`; `values_ID` → a `value_row`.
- **`value_row`**: the panel's arguments (title, text, image or media URL, colours a/b/c, header colours, layout, `is_slider`, `close_button`, `extra_ARGS`).
- Column suffixes encode type: `_NAME`, `_INT`, `_ANY` (a colour), `_PLAIN`, `_BOOL` (the **strings** `"True"`/`"False"`), `_TEXT_URL`.

### Panel types (`ServerScripts.get_sql_panel`, matched on `panel_types.id`)
| id | Class | Uses |
|---|---|---|
| 1 | `SimpleMusicSlider` | audio player (`img_src` = audio URL) |
| 2 | `PanelSlider` | `extra_ARGS` = comma-separated **panel ids** to cycle; those panels set `is_slider="True"` |
| 3 | `SimpleVideoPanel` | iframe (YouTube embed URL) |
| 4 | `CombinedSimplePanel` | text + image, `layout` 1/2 |
| 5 | `SimpleImagePanel` | image |
| 6 | `CombinedHeaderPanel` | title + text + image, `layout` 1/2/3 |
| 7 | `HeaderTextPanel` | title + text; optional close button; `extra_ARGS` = space-separated "read more" links |
| 8 | `TopHeaderTextPanel` | big title + text (the system's lead frame) |
| 9 | `SimpleTextPanel` | text |
| 10 | — | (`BasePanel`, unused) |
| 11 | `SimpleTable` | `text` = `key:value;key:value;…` |

Object panels whose `value_row.is_slider_BOOL = "True"` are not rendered on their own; they appear only through the slider that references them.

### Adding a DB system
1. Add a `systems` row, plus `objects`, `panels` and `value_row` rows. Copy the shape of Trappist (id 1), which is the cleanest complete example.
2. Add a `galaxy_placement` row (href = the system's name). **Compute** `l`/`b` from J2000 RA/Dec; don't guess them.
3. Optionally add `static/LinkImages/<name>.png` and `static/Icons/<X>.ico`.
4. Restart the server.

### Conventions
- HTML is built with f-strings and rendered `|safe`, so DB text is **unescaped**. That is acceptable only because the content is trusted. Escape any new user-facing input.
- Inline styles and handlers come from `StyleType.Style.*` and `StyleType.EventHandlers.*`. Reuse them instead of writing new raw strings.
- Sizes are in `vh`/`vmin`, and layout is absolute. The pages are designed for landscape desktop screens and are not responsive.

## 7. Galaxy view

The code in `static/Scripts/galaxy/` is the source of truth, and its comments are thorough. Read the comment above a constant before you change it. This section is the map, plus the lessons that cost the most to learn.

### 7.0 Modules (`static/Scripts/galaxy/`)

- **Imports are explicit and acyclic:** `config` → `util` → (`dust`, `backdrop`, `post`) → (`shaders`, `starfield`) → (`structures`, `landmarks`, `local`, `regions`, `hero`, `history`, `territories`; `territories` also reads `overlays`) → `view` → `main`. Keep it that way. Keep top-level code free of calls into other modules, so evaluation order never matters.
- **Every script and stylesheet is versioned** (2026-11-27, `starsystems/templatetags/versioned.py`): `{% vstatic %}` adds `?v=<10 hex of the file's SHA-256>`, `{% galaxy_importmap %}` maps each galaxy module's plain URL to its versioned one (so the modules' own relative imports are versioned too) plus `three` and OrbitControls, and `{% galaxy_preloads %}` builds the modulepreload list from the folder. Hashes are cached by mtime. A changed file gets a new URL, so a plain reload picks it up; the old `fetch(url, {cache: "reload"})` trick is no longer needed. **Import maps do not apply inside Web Workers**, which is why the star field is not built in one (it would need every `"three"` import rewritten).
- **Two servers on port 8000**: if a `runserver` without an address is already running (it binds 127.0.0.1:8000), the preview's `0.0.0.0:8000` server still starts, but `localhost` reaches the old one. Browse to the machine's LAN address to reach the new one, or stop the old one. The LAN origin logs a harmless Cross-Origin-Opener-Policy warning (plain HTTP).

### 7.1 Data (`db.sqlite3` → `starsystems/galaxy.py` → `json_script` → `GALAXY_DATA`)
- **Every place on the map is a database row** (owner, 2026-11-24), read on each request, so a new row shows on reload with no restart. Seven tables, plain column names (unlike the system-page tables), unmanaged models in `starsystems/models.py`, loaders in `galaxy.py` that drop NULL columns so the page can tell "not set" from zero:
  - `galaxy_placement` (href PK, label, l, b, d, x, z, fictional, source, note, hidden, sort, stars): where each star system with a page sits. Solar and AlphaCentauri are rows too. `stars` (2026-11-26) is what is drawn when you fly there: `temperature K:radius in Suns`, comma-separated, brightest first (`"5790:1.22, 5260:0.86"`); `galaxy.parse_stars` turns it into `[{t, r}]`.
  - `deep_sky` (name, alias, kind, l, b, d, radius, about, size): the named nebulae, clusters, remnants, planetaries and the Local Bubble (`kind` structure, with `radius`).
  - `planetary_systems` (name, note, l, b, d, stars): map-only real systems; `stars` as above, or `pulsar` (PSR B1257+12).
  - `fiction_places` (type system|object, name, source, note, anchor, l, b, d, x, z).
  - `spacecraft` (name, note, about, l, b, au).
  - `stellar_objects` (name, kind blackhole|neutron|star, note, about, l, b, d, mass, radius, radius_km → `radiusKm`, temperature, luminosity).
  - `territories` (name, color, source, note, sectors, points, members, fictional, hidden, sort; 2026-11-26, **empty**): nations and factions for the owner's own worlds. `sectors` is space-separated sector names (`K16 K17 L16`), filled as squares with a border round the set; or `points`, a polygon `X,Y; X,Y; …` in the readout's galactocentric kly; `members` names places on the map (comma-separated) that take its colour while the layer is on. While the table is empty the layer's switch is hidden. Tested with two temporary rows (a sector set and a polygon), then removed.

  Row counts on 2026-11-26 (after the content round the same day, which added 93 rows: 44 deep-sky objects, 30 stellar objects, 14 planetary systems and 5 fiction places at real stars, every l/b computed from J2000 RA/Dec): `galaxy_placement` 8, `deep_sky` 106, `planetary_systems` 22, `fiction_places` 29, `spacecraft` 5, `stellar_objects` 52 (12 black holes, 13 neutron stars, 27 stars), `territories` 0. New photos come from each object's English Wikipedia lead image (free licences only, charts and maps skipped), into `static/Images/DeepSky/` with their entries in `image_sources.py`.

  Rows are listed in `id` order (placements by `sort`). The galaxies, the arms, the celestial pole and the credits stay static in `galaxy.py`. The move was checked by comparing the page data before and after: identical. Card photos still come from `image_sources.py` (§7.8).
- The placement is keyed by href. Real systems give `l`/`b` (deg) and `d` (ly). Fictional ones give `x`/`z` (ly) plus a `source`. `hidden: True` keeps a system out of the view.
- `DEEP_SKY` holds 61 named nebulae, clusters, remnants and planetaries, plus the Local Bubble, keyed by `kind`. They are drawn **artistically and bigger than life** (`ARTISTIC` in `landmarks.js`, all alphas scaled by `ART_BRIGHTNESS` 0.56 - 0.78 until 2026-11-25, when the owner found too much standing out at every zoom - and big nebula envelopes × 0.8 (`BIG_ENVELOPE`) so no one object shouts): an envelope (the far look, with a floor), detail wisps and knots that lean one way per object, rings for planetaries and remnants, and member stars for clusters and for the young stars inside nebulae. **Sizes are world sizes**: a sprite of size s spans about s × 83 ly until it hits its on-screen cap (520px for named ones), so a nebula keeps growing as you fly in. The old 64px cap is what made them read as stickers. Each entry has `about` and `size` (real extent, ly) from `DEEP_SKY_ABOUT`, shown on the info card. Positions stay exact. The landmarks use their own seeded PRNG, so adding one never reshuffles the star field.
- **Arms:** Norma, Outer, Scutum–Centaurus, Sagittarius–Carina, Perseus, the Orion Spur, and the Near and Far 3 kpc Arms (`THREE_KPC_ARMS`; names only, since the artwork doesn't resolve them). All are in `registry` under "Spiral arms", are listed in the Nebulae & clusters panel under "Structure", and all show from the Whole galaxy view.
- `PLANETARY_SYSTEMS` (8 entries, Kepler-186 to OGLE-2005-BLG-390L) are **real systems beyond the neighbourhood with no page**. They are map-only: hollow-ring markers on the systems layer that fade in near them, and a click flies there. Their `l`/`b` were computed from J2000 RA/Dec.
- `FICTIONAL_PLACES` hold fiction **set in the Milky Way only**, on their own **fiction** layer and drawn dashed, violet and italic. `type` is `system` or `object`:
  - Star systems: Widow, Sahrabarik and Aralakh (Mass Effect), 40 Eridani (Vulcan), Epsilon Eridani (Reach) and Canopus (Arrakis). Trebia (Mass Effect, has a page) lives in `galaxy_placement`.
  - Objects: Arcturus Station, the Collector Base, and Gargantua's wormhole by Saturn.
  - Since 2026-11-24 also Alien (Zeta Reticuli), Dune (Caladan, Giedi Prime), Halo (Harvest), Contact (Vega), Foundation (Trantor, Terminus), Warhammer 40,000 (Cadia, Macragge, by eye), Babylon 5, Wolf 359, the Charon Relay and the 2001 monolith.

  A place whose story names a real star sits at it (`anchor`); the rest are `x`/`z`. **Mass Effect positions are read off the ME3 galaxy map** (cluster numbers from a guide's annotated map), deprojected for the map's tilt (vertical × 1/0.7) and rotated and scaled so the Arcturus Stream lands on the Sun; Omega comes from the ME2 map, beside the Hourglass Nebula. Fandom blocks automated fetches; its ME1 image map is readable in the browser pane. Star Wars and other fiction set elsewhere were removed on purpose.
- `SPACECRAFT`: Voyagers 1 and 2, Pioneers 10 and 11, New Horizons; directions computed from RA/Dec, distances in AU for late 2026. They are local-level object markers that part from the Sun only near the bottom of the zoom (`LOCAL_MIN_DISTANCE`).
- `STELLAR_OBJECTS` (2026-11-24): real black holes (Sgr A*, Cygnus X-1, Gaia BH1-3 …), neutron stars (Vela, Crab, SGR 1806-20 …) and remarkable stars (Betelgeuse, Eta Carinae, VY CMa …), with `mass`/`radius` in Suns, `radiusKm`, `temperature` (K), `luminosity` (Suns) and `about`. l/b computed from RA/Dec. Drawn by `buildStellarObjects` (accretion ring, cyan point, temperature-tinted glow) on the **objects** layer; Sgr A* is not drawn there because the core already is.
- **A place opens only from the click that flies there** (owner, 2026-11-25; before, the nearest place to wherever a flight landed opened, so a click on Sol opened Canopus). A row or a label calls `visit(item)`, which flies with `{ open: item }`, and `stepFlight` opens exactly that item on arrival; nothing ever opens by proximity. **Every place does this, star systems with pages included** (owner, 2026-11-26): their labels and rows fly there and open a panel whose **Open the … page** button (`.DetailPage`) is the way to the page; Sol too (the Sol button bottom right only flies, it opens nothing). Every place with a story (`this.infoItems`) has a `close` distance, the `layers` it needs and a `hero` (what to draw). **The camera is posed, not aimed** (`visit`): it settles 1.4-1.9 × `close` from the place, on the far side from the core (± 37°, random each time), 64-78° from the pole. Then **the view is a still picture** (owner, 2026-11-27, replacing the turnable close-up of the day before): `controls.enabled = false`, nothing turns, pans or zooms until Back or Esc. **Each place has its own pose** (`compose(item, distance)`, deterministic): a sweep of 48 directions × 5 heights round the place, scored so the galaxy's heart sits left of the object (the panel is right) and up on the horizon - the bright band crosses the top of the picture and the object stands against darker sky below; from the halo the galaxy lies below-left; at the core it looks in from outside; a black hole is seen at about 70° to its disk's axis. The camera settles at 0.94 × `close`. **Back returns to where the place was clicked** (owner, 2026-11-27, settling a back-and-forth: "otherwise we will be fighting it indefinitely"): `visit()` stores `returnView` (pivot, distance, angles, anchor) unless a place is already open or being flown to, so going from one open place to another keeps the first view; Back or Esc flies there in 1.4 s. `settleOnPlane` (pivot onto the disk, camera kept) is still there, used only if no view was stored.
- **The drawn object renders in its own pass** (`HERO_LAYER` 2 in config.js, rendered by `PostPipeline.render` after the soft layers are merged, before the bloom; owner, 2026-11-27: the stars looked see-through - the half-resolution haze, bulge glow and off-plane sheets were added on top of them). ### 7.2 Scene conventions
- 1 unit = 1,000 ly. The galactic centre is at the origin, the disk is the XZ plane, the Sun is at +Z, longitude 0 points to −Z and longitude 90 to −X.
- The arm skeleton is log spirals at a 12° pitch (`ARMS[].crossing` is where each arm crosses the Sun–centre line) plus the Orion Spur. It drives the dashed outlines and the labels. The crossings (10.9 / 17.9 / 21.8 / 32.7) are **fitted to the backdrop** (2026-11-23): a phase sweep at the shared 12° pitch over the contrast-normalised artwork, taking the ridges. The old symmetric set put Perseus and Scutum in the gaps. A free pitch per arm aliases arms onto each other a turn apart, so keep it shared. `rMax` ends each line where its arm fades, and lines taper at both ends (vertex alpha). Re-fit if the backdrop or `BACKDROP.rotation` changes.
- The bar axis is `BAR_ANGLE` = 117°, tied to `BACKDROP.rotation` (16°). If one changes, so must the other.
- There are two levels: the whole galaxy, and a Sun-centred local view at **true scale** (since 2026-11-23; the log scale is gone). Systems and landmarks use `truePosition` at both levels, so landmarks have one set of labels (`level: "any"`). The local view fades in between `LOCAL_ENTER` 2.6 and `LOCAL_FULL` 1.5 units from the Sun. `minDistanceAt()` drops the zoom limit to `LOCAL_MIN_DISTANCE` (2e-6 units, about 130 AU, so the Voyagers separate) near the Sun and blends back to 0.8 away from it, and `camera.near` follows the camera distance (×0.02, clamped 1e-8…0.01; nothing writes depth, so the tiny near plane costs nothing). Rings sit at 10/100/1,000 ly (`LOCAL_RINGS_LY`), and each ring label shows only while its ring is a readable size. While the local view is more than half in, `#GALAXY_SCALE_NOTE` says so ("Local view · true scale · rings at 10, 100 and 1,000 ly").

### 7.3 What is drawn
- **The backdrop** is R. Hurt's NASA/JPL-Caltech artist's concept (public domain). It is an impression, not survey data. It is a **slice stack** (`BACKDROP.slices: 5`): the mid-plane sheet is sharp, and the off-plane sheets are blurred, twisted, warped and torn by noise (`uTear`). All four tricks together are what stop ghosting face-on and the venetian-blind look edge-on, so check both views after touching any of them. The backdrop has no toggle.
- **The star field is sampled from the backdrop.** `buildGalaxyFromImage()` builds a brightness CDF (exponent 2.2) and samples `BACKDROP.stars` (2.1M, a budget: flocculent thinning removes about a fifth). Each star takes its pixel's hue, tinted towards `STAR_TINTS`. **`GALAXY_TINT`** (config.js, R 1.15 G 0.94 B 1.12, luminance-balanced; warmer since 2026-11-24 at the owner's request) then gives the stars, the haze and the backdrop (`uTint`) a slight violet cast: an artistic choice by the owner, since nobody has seen the Milky Way's colour from outside. The nebulae, the core and the galaxy photographs are not tinted. `BACKDROP_MATRIX` is shared by the sampler and the slices, so the two cannot drift apart.
- **There are three stellar components:** the thin disk, the thick disk (260k) and the halo (110k). They share one `Layer`, and its capacity must cover their sum. Fix perceived flatness with these components, never by thickening the thin disk.
- **Haze:** gas (10k), cirrus banks (2k), inter-arm fill (3.8k; picks dim pixels uniformly instead of from the CDF), and knots (3.6k).
- **Populations by radius** (2026-11-28): thin-disk stars, gas and the backdrop lean yellow-white in the inner disk (4-7 kly in, fading out 11-22) and blue in the outer (20-38 kly), at their own brightness, before `GALAXY_TINT`; before this every arm was one lavender. `INNER_DISK`/`OUTER_DISK` in starfield.js, the same numbers in `BACKDROP_FRAGMENT` (from afar most light is the painting). No random draws.
- **Knots come in strings** (2026-11-28, `chainKnots` in starfield.js): picked as before, then regrouped in fives - a bigger head and four smaller followers 0.12-0.5 kly apart along the rotation - on their own seeded generator, so nothing later moves. Close in they soften (`uSharpness` 9 → 5) and dim (× 0.45 at full `closeGain`): hard dots up close were pink confetti.
- **HII regions** (`regions.js`, `buildHII`, owner 2026-11-26): pink beads along the arm skeleton, 0.35-0.75 kly inside each ridge and only where the painting is lit (`litAt` reads the sampler; none on an empty gap), every 0.55-1.45 kly, thinning towards the rim: a soft glow (0.5-1.6 kly, alpha 0.1-0.18, `materials.hii`) with 2-6 brighter knots (`materials.hiiKnots`), both taking the dust lane. Quiet from afar, a lit cloud close in.
- **The bar** (`buildBar`): 900 soft warm sprites on the half-resolution layer along `BAR_ANGLE`, flat out to ~9 kly and fading by 14, beyond the boxy bulge (which has its own glow), × 0.25 from inside the core.
- **Bloom by zoom** (owner, 2026-11-26): `uBloom` 0.4 close to 0.74 far and the threshold 0.72 to 0.54, over `smoothstep(8, 90, cameraDistance)`: from afar the galaxy glows as a light source, close in the stars stay crisp.
- **Arm edges** are coloured from the artwork's radial brightness slope: blue outside, warm inside. `INTER_ARM_TINT` makes the gaps redder.
- **Controls:** the bottom-right group has the **angle dial** (`#GALAXY_ANGLE`, `updateAngle`: the disk as an ellipse that flattens towards edge-on, degrees above the plane, and a dot on the side the galactic centre is on), a core button (`data-action="core"`, amber) and a Sol button (`data-action="sun"`), then zoom out and zoom in. (A pick-a-centre button was tried and removed on 2026-11-26.) In the corner beside them the **eye button** (`#GALAXY_UI_TOGGLE`, or the H key) hides everything but itself: panels, labels, layers, controls, the info card, and the map overlays (arm outlines, local rings, bearings, sectors). It sets `.UiHidden` on the view and is not remembered.
- **The core:** a boxy, peanut-shaped bulge (`BULGE`, `buildCore`, `buildBulgeGlow`), a nuclear cluster, and 70 black holes drawn as ring glyphs, visible between about 5 and 46 units. The shapes are real; the sizes are schematic. `uCoreFade` hands the artwork's bulge over to the 3D core up close.
- **Scattered deep sky:** about 2,000 unlabelled filler objects. Of its ~240 halo globulars every third is only a faint point with no painted cluster, and the rest vary in brightness (owner, 2026-11-27: edge-on the halo read as polka dots; the Milky Way has about 160). The same random numbers are drawn in the same order, so the star field is unchanged. The core's 70 black-hole rings also fade out near edge-on (elevation 0.12-0.35), where they stacked over the bulge like bubbles. Each records its kind (`layer.objects`, which draws no random numbers, so the star field is unchanged), and they get the landmarks' painted look through `buildDeepSky(objects, { amount: 0.6, cores: false, sizeScale: 2.6, cap: 160, spots: true })` (lite 0.4). **`spots`** (owner, 2026-11-24: the same spots round the galaxy as round the Sun) gives their clusters the named ones' member stars - full count, bright ones among them - a little smaller and dimmer (8 px, sharpness 10, × 0.7), and their wide-view fade is × (1 − 0.9 wide). Compared at distance 12 round the Sun and round (−14, 0, 12): the same clustered, coloured spots. A denser filler (4,400 at nearly the named look) was tried and reverted on 2026-11-24: the owner wanted the Sun's area to stop standing out, which the named fade above does. If the view feels crowded, reduce these, never the catalogue.
- **Edge-on, the plane's hard points step back** (2026-11-27, `edgeQuiet` in `frame()`): star-forming knots, HII knots and the filler's clusters and centre dots go to 0.3 below about 9° of elevation, full from there up. Measured at the core edge-on, the haze, knots and filler made the mid-plane brighter than the band around it, filling in the dark lane. The lane itself went up a little: `DUST.laneDepth` 0.1 → 0.13, `softLane` 1.0 → 1.25. A sharper dark stripe would need the lane maths changed (the slab spreads the dust); not done.
- **Keep the bulge free of star formation.** The painting's bulge is warm gold, so any "pick the reddish pixels" test lands on it and the core close-up turns into pink confetti. Knots are gated out below r = 8.5. Scattered nebulae, remnants and planetaries thin out below r = 9, and "pink" requires low green (`r > g × 1.18`) as well as `r > b × 1.1`. Any new sampled population needs the same gate.
- **Galaxies** are photographs on fixed planes whose normals point back at the Sun, so each carries its real tilt. They are median-filtered to strip foreground stars (radius 3 for M31/M33 and 2 for far spirals; the LMC and SMC are left as they are). To tune apparent size, change `display`, never `size`. After you add a galaxy, re-check the brightness ladder.
- **Surroundings:** 26k shell stars, about 1,600 warm "galaxy dots", and 120 far-field quads (dim textures, brighter quads).

### 7.4 Post-processing (new in 0.8.2.2)
- The scene renders into a **half-float HDR target**, then goes through bloom (6 mip levels), a shouldered tone curve (on luminance since 2026-11-28: `1 - 1/(1 + L + L²/2)`, hue kept in the mids, highlights leaning back to a per-channel curve and warm pinks drifting to gold, only the brightest light whitening; the old per-channel `1 - exp(-x)` made the bulge a flat cream plateau - near-white pixels at the core close-up are about half now, mids unchanged), saturation, vignette, a shadow tint and dither (`POST`, `PostPipeline`). `THREE.ColorManagement` is **off**: colours are authored display-referred.
- **Lens flare** (owner, 2026-11-27; `lensFlare` in `COMPOSITE_FRAGMENT`, `view.updateFlare`): drawn, not sampled. The view picks one source - a drawn star while one is open (tinted by `artColor`), else the galactic core - and passes its screen position and strength (`uFlarePos`, `uFlareAmount`, `uFlareTint`); the shader draws five ghosts (mostly a thin rim split slightly by colour, over a faint fill that empties towards the middle, since 2026-11-28: solid discs read as stickers) along the line through the frame's middle in the house colours, a thin halo ring and a short level streak. No texture reads; skipped while the amount is 0; compiled out in lite (`FLARE` define). The core's flare (`POST.flare` × 0.4) fades off screen, edge-on, within 5-14 units of the core (camera to core, not to the pivot) and partly in the local view. Measured A/B at the opening view: no difference beyond noise. A first version made ghosts from a blurred bloom level; they were shapeless smudges and it was replaced.
- Soft layers (haze, bulge glow, off-plane sheets) render at **half resolution** (`SOFT_LAYER`, `SOFT_SCALE`) and are composited before the bloom.
- **This invalidated the old "saturation" reasoning.** Earlier tuning assumed an 8-bit frame clipping at 765 (sum of RGB), with the edge-on band about 2.5× over. Lane strengths were cranked up to cut through that clipping. With HDR "nothing clips now", and `DUST.laneDepth` was retuned down to **0.1**. Older notes quoting 0.105, 0.135 or 0.016, or peak values out of 765, are pre-HDR. Re-measure before relying on them.

### 7.5 Dust and extinction: rules that cost the most to learn
- **Don't reintroduce dust as geometry.** Sprite dust was built and deleted three times, and it always read as stains. Extinction is computed **per star in the vertex shader** (`LANE_GLSL`): a gaussian slab (`laneHeight` 0.34 kly) integrated in closed form with an `erf` approximation. **Write it as a mean density times path length, not as an integral in t**, or the column is lost exactly edge-on.
- **Arm dust is read from the artwork** (`dustMapFrom`, thresholded). It darkens the backdrop (`backdropDepth` 3.3, an optical depth under Beer's law) and dims stars (`aDust`, `armDepth` 7.6; both raised 2026-11-25 from 2.7 and 6.2, when the owner asked for more dust). **Dust is black** (owner, 2026-11-24): every absorber uses `DUST_COLOR` (config.js, 0.88 : 1 : 1.14 of the green depth, `DUST_COLOR_GLSL` in the shaders) instead of the physical 0.75 : 1 : 1.32, which made the lanes rust-brown. Threshold the map, or the whole disk turns to mud. **Filaments** (`addFilaments` in `starfield.js`, owner 2026-11-26) are written into the same map: a thin, broken lane 0.55 kly inside each arm's ridge, and feathers every 0.6-1.6 kly from the inner edge out across the arm at 35-60° to it, 1.2-3.6 kly long, only where the painting is lit. They darken the backdrop and the stars like any lane; never as geometry. Own seeded generator, so the star field is unchanged.
- **The two dust terms are gated by elevation in opposite directions.** The flat-view lane fades out between 0.18 and 0.30, and arm dust fades in between 0.10 and 0.26. Stars with `aDust` < 0.012 skip the maths, which is what makes per-star dust affordable.
- **Background objects are dimmed by disk dust** (`dustColumn` clipped analytically to the slab, then `diskTransmission`). Labels under 0.3 transmission are hidden. The core also dims as you drop into the plane (`uExtinction`, per star by height).
- The near/far asymmetry seen just off edge-on is real. Don't balance it out.
- **The edge-on lane depends on the camera angle as much as on the dust.** From 1.3° above the plane (the old 88.7° Edge-on button), every sight line to a star below the plane crosses the slab at a grazing angle *inside* the disk. The whole lower half of the band dimmed together, with no light below the lane, so it read as a shaded band. From 0.5° (the button is now 89.5°) those sight lines cross the plane outside the disk's dust, and the band is lit on both sides of a dark stripe. Measured at 2.3 MP, as summed-RGB row means across the band: 586 → 359 → 465. If the lane "disappears" again, check the viewing angle before touching `laneDepth`.
- **Measure a lane by toggling it** (`uLane` on and off, per-channel frame means) and compare the mid-plane against the wings, never the frame mean.

### 7.6 Camera, composition, UI
- **Controls:** left-drag pans, right-drag orbits, the wheel zooms. This mapping is deliberate. Nothing moves on its own unless Settings → Idle turn is Slow (off by default): then, after 5 s untouched (20 s until 2026-11-27), OrbitControls' `autoRotate` turns the view about its pivot at `autoRotateSpeed` −0.1 with a real `dt` (one turn in ten minutes, clockwise from the north, the galaxy's own sense). Any touch, a flight or an open place stops it. It costs nothing: the frame is drawn every vsync anyway. A true differential spin (the inner disk faster) would mean moving every star and every label; not worth it for a turn nobody could see in a lifetime.
- **Touch matches the mouse:** one finger pans, two fingers pinch and turn (`TOUCH.DOLLY_ROTATE`). On coarse pointers the hint text says so. On narrow screens the hint sits top right and fades after the first touch.
- **Keyboard** (`bindKeyboard`): WASD and the arrows, held, slide the centre point along the plane (`panByKeys`, see below), Shift+arrows turn and tilt, `+`/`-` zoom, Home shows the whole galaxy, H hides and shows the interface. Arrows act only when the map, or nothing, has focus, and keys are ignored in form fields. The canvas is focusable (`tabindex="0"`, `role="application"`) and shows an inset ring on `:focus-visible`.
- **WASD and the arrows move the centre point** (owner, 2026-11-26, after a free-flying WASD was tried and dropped; `panByKeys`, read every frame from the held keys in `this.keys`): the pivot and the camera slide together along the plane - W/Up away from the viewer, S/Down towards, A/D/Left/Right sideways - without turning or climbing; Shift with WASD is three times faster. Half the camera distance per second. ### 7.7 Performance and measurement
- **The load is sliced** (2026-11-27): `buildGalaxyFromImage` is async and hands the thread back about every 12 ms (checked every 8,192 stars, resumed through a MessageChannel, which hidden tabs do not throttle), and `frame()` draws nothing while `this.building`. The random draws are unchanged, so the star field is identical (checked by checksum). Total build time is the same; the page stays responsive and the bar moves from 0.6 to 0.9.
- **The stars are culled by chunk** (2026-11-27, `chunkGeometry` in util.js): 12 × 12 kly columns, plus eight halo octants for anything more than 1.6 kly off the plane - 96 chunks at full detail, 93 in lite - so three.js skips those outside the view. Blending is additive, so the picture is unchanged. Measured back to back on/off: close over an arm 2.6-3.3 against 4.5 ms, near the Sun 3.3 against 4.3, at the core 5.1-5.6 against 6.0, the whole galaxy the same. Splitting costs about 100 ms at load. One frame is drawn with culling off behind the loader so every chunk is uploaded at once (no hitch the first time one turns into view).
- **Memory** (2026-11-27): `releaseAfterUpload` drops the JavaScript copy of the star chunks, the haze and the knots once they are on the GPU. JS heap at full detail: about 122 MB before, 29 MB after (once garbage collection has run). Nothing may read those arrays afterwards.
- **The side lists** fill a row's live figures only when it scrolls within 300 px of view (`IntersectionObserver`, `fillDistances`), and off-screen rows skip layout and paint (`content-visibility: auto`; an empty figures line holds 50 px so nothing jumps). The page went from about 9,200 elements to 5,600.
- **Frame pacing** (owner, 2026-11-26: full detail kept the Arc laptop at full load; a clock that runs ahead of `now` - hand-driven frames from the console - is reset rather than freezing the view): `frame()` draws at most 60 fps, and 30 fps once the view has been still for half a second (`lastMove`, set by the controls' `change` event; a flight counts as moving). Twinkling and the drawn places carry on at 30. With the lower full-tier pixel ratio, this is most of the saving; star counts are unchanged.
- **Measured 2026-11-19, after the HDR change and the module split.** Each figure is milliseconds per frame from `gl.readPixels` around 24 renders, at 1920×1200 (2.30 MP) on the Arc 140T laptop, as two back-to-back passes. The 60fps budget is 16.6ms.

  | View | full (2.26M points) | lite (1.04M points) |
  |---|---|---|
  | Opening (`START`) | 6.2 / 5.8 | 5.4 / 4.1 |
  | Whole galaxy | 5.9 / 6.1 | 4.1 / 4.5 |
  | Edge-on (89.5°) | 5.6 / 5.7 | 3.8 / 3.8 |
  | Galactic core (24 units) | **8.5 / 8.5** | 6.0 / 5.9 |
  | The Sun (local view) | 5.2 / 5.2 | 3.6 / 3.5 |

  The core close-up is the worst frame, as it always has been, and it is where to look first if a budget tightens. Time from navigation to the loader lifting was 4.6s full and 2.3s lite. That was measured in a throttled, hidden pane, so treat it as an upper bound. The JS heap is about 108MB at full detail.
- **Quality tier (`config.js`, `detectQuality`).** "lite" keeps 45% of the stars (thin disk, thick disk and halo) and 60% of the haze, multiplies their alphas by the inverse (`Layer`'s `alphaScale`, so count × alpha and therefore exposure hold), caps the pixel ratio at 1.25 and drops one bloom level. Full caps it at 1.5 (2 until 2026-11-26). It is chosen automatically for a coarse pointer on a screen under 600px, ≤4 CPU cores or ≤4GB `deviceMemory`. `?quality=lite|full` overrides it and is remembered in `localStorage` (`galaxyQuality`); `?quality=auto` forgets the override. "About this map" shows the current tier and a link to switch. Arms, dust, labels and landmarks are identical in every tier. **"extreme"** (2026-11-24) is **never chosen automatically**, only by `?quality=extreme` or Settings → Detail: it is about the picture, not just the count (`config.js`): the best picture at any cost (owner, 2026-11-24): stars × 3, haze × 2.5, star-forming knots × 2, shell stars and galaxy dots × 2 (`SURROUNDINGS_DENSITY`), each fainter to match (6.9M points, JS heap about 300 MB); **supersampled** at 2 × the screen's pixel ratio, up to 3 (`PIXEL_RATIO`); soft layers at full resolution (`SOFT_SCALE` 1); nine backdrop slices; seven bloom levels; maximum anisotropic filtering on the backdrop. Measured in a 1024×768 pane on the Arc laptop (a 2048×1536 buffer): 42 ms at the opening view, 65 ms at the core, against 9.5 and 8.7 ms in full - for strong desktop GPUs only. The deep-sky filler is the same in every tier. **If you change a star count or alpha, check every tier.**
- **Don't allocate per star.** `pixelToPlane()` writes into a passed-in vector; allocating per call was 4× slower.
- **Haze costs fill area, so raise alpha before count or size.** Sprite caps (`uMaxSize`) tighten as the camera approaches.
- **Density and brightness are separate dials.** Keep count × mean alpha constant. `uGain` lifts faint stars close in, so if you halve alpha, re-check the close-up.
- **Measure frame cost with `gl.readPixels` around N renders, not with fps.** The pane caps at vsync and throttles to about 2 fps when it isn't visible. GPU power state drifts absolute numbers by 2×, so A/B settings back to back.
- **`frame()` returns early when the view is stopped.** A sweep that calls `stop()` and then `frame()` measures nothing.
- **Debugging:** `window.galaxyView`; `placeCamera()` jumps instantly and `flyTo()` animates. Screenshots can lag a frame behind. Module-scoped constants (`DUST`, `BACKDROP`, …) are not on `window`, so to A/B a uniform, wrap `galaxyView.post.render` and set the uniform there: `frame()` rewrites uniforms every frame, so anything set before it is lost.

### 7.8 Images: sources, downloads, compression (2026-11-24)

- **Downloaded, never hotlinked.** The owner chose local copies: the galaxy page makes no external requests, and hotlinked images on the system pages already rot. Each local image keeps its source in `starsystems/image_sources.py`.

Re-running `download.py` (it now skips a refused file and carries on) and then `compress.py` and `gen_sources.py` adds it; nothing else changes.
- **Fiction has reference images** (owner, 2026-11-24: images from games, films and books are fine, always with the reference; since 2026-11-25 they fill the left like any photo, with a dashed violet edge). If the site is ever published beyond the owner's own use, review these first: fair use on Wikipedia does not automatically cover another site.
- **Wikimedia rate-limits scripts hard.** Thumbnail requests start failing with HTTP 429 after a few dozen. Batch the metadata (one `imageinfo` query per 45 titles), wait 20s between image requests and back off two minutes on 429. Do not put the owner's email in the User-Agent.
- **Compression is ffmpeg** (installed with `winget install Gyan.FFmpeg`; binary at `%LOCALAPPDATA%\Microsoft\WinGet\Links\ffmpeg.exe`). Card photos: 1280px or 960px renders (Wikimedia now serves only its standard widths - 250, 330, 500, 960, 1280, 1920 - and answers 400 to any other) scaled to **960px** wide (or the source width, if less) with Lanczos - sharp at half a 1080p screen in the full view, alpha premultiplied onto black, metadata stripped, mjpeg `-q:v 2`:
  `ffmpeg -i in -vf "scale='min(960,iw)':-2:flags=lanczos,premultiply=inplace=1,format=yuvj420p" -frames:v 1 -q:v 2 -map_metadata -1 out.jpg`
  SSIM against a lossless render of the same resize is 0.96 to 0.99 (the misses are film grain in dark sky); about 230 KB per image, 20 MB for the 86 photos (they were 640px and 9.6 MB until the full view). With the 19 fiction reference images the folder holds 105 files, 22 MB, matching the 105 entries in `IMAGE_SOURCES`. The content round of 2026-11-26 added 54 more (159 files, 35 MB, 159 entries): first each object's Wikipedia lead image, then for those whose lead image was a chart a Commons search by name. The search returned namesakes (a butterfly, a car, a warship, a rocket), so every pick was checked on a contact sheet and 14 were dropped; most bright stars (Arcturus, Antares, Spica, Altair...) still have no photo, because Commons has no honest close picture of them.
- **The backdrop** (`GalaxyBackdrop.jpg`, 1350²) was re-encoded at `-qmin 1 -q:v 1`: 955 KB → 425 KB at PSNR 49 dB, SSIM 0.992 against the original. The star field is sampled from it, so the field shifted imperceptibly; if the backdrop is ever replaced, keep the encode at q 1 and re-check the arm fit (§7.2). **The galaxy photos were left alone**: they are already 5 to 60 KB, and re-encoding at the same quality made every one of them bigger.

## 8. General conventions and gotchas

- Use CRLF in existing files (endings are mixed). `requirements.txt` is UTF-16.
- Asset names are case-sensitive on Linux; Windows hides mismatches.
- Installed apps are only `starsystems`, `staticfiles` and `compressor`. There is no auth, sessions or admin, so don't add features that need them.
- The Sass toolchain is kept on purpose for future SCSS, even though nothing uses `{% compress %}` yet.
- The settings are for development only. There is no production static serving (`STATIC_ROOT = compiled/`) and no deployment config.
- Commit messages are version numbers (`0.8.2.2`, `0.8.2.1b`, …).
